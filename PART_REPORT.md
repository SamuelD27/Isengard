# Part 2 Report: AI-Toolkit Training Backend Correctness

## Bug Root Cause Analysis

### Problem Statement
ERR-001: AI-Toolkit sample images were not displayed in the GUI during production training, while mock training worked correctly.

### Root Cause
The `_run_aitoolkit_training()` function in `apps/api/src/services/job_executor.py` had three critical issues:

1. **No sample directory monitoring**: The function did not monitor AI-Toolkit's output directory for generated samples during training.

2. **No sample copying**: Samples generated by AI-Toolkit to its temp directory (`{output_dir}/{job_name}/samples/`) were never copied to the job samples directory (`get_job_samples_dir(job_id)`).

3. **No sample_path in progress callback**: The `TrainingProgress` callback never included `sample_path`, so the UI couldn't detect new samples.

### AI-Toolkit Sample Output Structure

Through analysis of `vendor/ai-toolkit/jobs/process/BaseSDTrainProcess.py`:

- **Sample location**: `{training_folder}/{job_name}/samples/`
- **Filename pattern**: `{timestamp}__{step:09d}_{index}.{ext}`
  - Example: `1724085406830__000000500_0.jpg`
  - `timestamp`: Unix timestamp in milliseconds
  - `step`: Zero-padded 9-digit step number
  - `index`: Sample index within the step (0-based)
  - `ext`: Image extension (jpg, png, webp)

### Mock vs Production Comparison

| Aspect | Mock Training | Production (Before Fix) |
|--------|--------------|------------------------|
| Sample location | `get_job_samples_dir(job_id)` | Temp dir (lost on cleanup) |
| Sample naming | `step_{step:05d}.png` | AI-Toolkit format |
| sample_path reported | Yes | No |
| Samples in result | Yes | No |

## Fix Implementation Details

### File Modified
`apps/api/src/services/job_executor.py` - Lines 421-647 (`_run_aitoolkit_training` function)

### Changes Made

#### 1. Sample Monitoring Setup (Lines 492-500)
```python
# Sample monitoring setup
samples_generated: list[str] = []
samples_dir = get_job_samples_dir(job_id) if job_id else None
aitoolkit_samples_dir = output_dir / job_name / "samples"
last_sample_check = time.time()
copied_samples: set[str] = set()  # Track already-copied samples
SAMPLE_CHECK_INTERVAL = 2.0  # Check every 2 seconds
# Regex to parse AI-Toolkit sample filenames
AITOOLKIT_SAMPLE_PATTERN = re.compile(r".*__(\d+)_(\d+)\.(jpg|jpeg|png|webp)$", re.IGNORECASE)
```

#### 2. Sample Monitoring in Training Loop (Lines 540-571)
Added periodic check every 2 seconds to:
- Scan AI-Toolkit samples directory
- Parse filenames to extract step number and index
- Copy new samples to job samples directory with standardized naming
- Track copied samples to avoid duplicates
- Log copy events for debugging

#### 3. sample_path in Progress Callback (Lines 573-587)
```python
progress = TrainingProgress(
    current_step=current_step,
    total_steps=total_steps,
    loss=current_loss,
    message=f"Step {current_step}/{total_steps}",
    sample_path=latest_sample_path,  # NEW: Include sample path
)
# Clear latest_sample_path after reporting to avoid duplicate notifications
latest_sample_path = None
```

#### 4. Final Sample Check (Lines 591-612)
After training completes, performs one final scan to catch any samples generated in the last moments of training.

#### 5. Samples in TrainingResult (Lines 619, 629, 642)
All `TrainingResult` returns now include the `samples=samples_generated` field.

### Naming Convention
- Source: `1724085406830__000000500_0.jpg`
- Destination: `step_00500_0.png`
- Format: `step_{step:05d}_{index}.png`
